# Gugu Agent Desktop UX Polish Roadmap

更新时间：2026-06-19

## 目标

第一轮体验打磨优先解决用户最容易失去信任的场景：卡住不知道原因、多个会话串状态、停止不确定、权限等待不清楚、错误没有下一步。所有改动按小步快发推进，每个阶段都能独立打内测包。

## 已知体验问题

| 优先级 | 问题 | 期望体验 | 验收方式 |
| --- | --- | --- | --- |
| P1 | 多个 Session 同时运行时状态可能混淆 | 消息、权限、停止按钮和活动面板都绑定当前 Session | 同时运行两个会话，分别停止其中一个，另一个继续 |
| P1 | 长时间思考、Write、Bash、附件解析时用户不知道发生了什么 | 活动面板显示当前阶段、耗时、可能原因和下一步 | 构造长 Bash、Write、附件解析和模型无响应场景 |
| P1 | 等待权限时弹窗或活动面板不够明确 | 明确显示等待哪个工具、为什么需要确认、用户下一步 | Bash/WebFetch/Write/ExitPlanMode 权限场景 |
| P2 | 附件解析失败或超时提示太技术化 | 显示本地/托管/GLM 路径、失败原因和可操作建议 | 大文件、图片超时、格式不支持、GLM 未配置 |
| P2 | “从这里继续”失败时暴露内部错误 | 显示中文恢复提示，不展示堆栈或内部日志 | 模拟长响应中断后点击继续 |
| P3 | 侧栏按时间分组对项目型工作不直观 | 按项目目录分组，可折叠，组内按更新时间排序 | 多项目会话、未归类、目录丢失、搜索命中 |
| P4 | 高频操作缺少系统化快捷键 | 新建、搜索、停止、运行、侧栏、标签切换都有快捷键 | 键盘回归测试和手动 smoke |
| P5 | 小白用户看不懂能力是否可用 | 能力体检只显示可用/需要处理/可选增强 | RTK、MCP、Skills、Computer Use、GLM 状态 |

## 分期

- P0：体验基线与发布 smoke 清单。
- P1：运行可信度：Session 隔离、停止、权限等待、长任务提示。
- P2：错误与附件体验：中文错误、解析路径、恢复动作。
- P3：项目分组侧栏：项目目录分组、折叠、尾部统计。
- P4：快捷键体系：高频操作快捷键和帮助提示。
- P5：新手信任与能力体检：入口模板、能力健康状态、发布验收固化。

## 发布前 Smoke Checklist

每次桌面内测包发布前至少跑以下场景：

- 新装启动：能打开首页、创建会话、发送一条普通消息。
- 覆盖安装：旧版本数据、会话列表、设置和激活状态保留。
- 热更新：下载、安装、重启后版本号正确，快捷方式可启动。
- 多会话：两个 Session 同时运行，停止其中一个不影响另一个。
- 权限：Bash、Write、WebFetch、ExitPlanMode 弹窗能确认/拒绝。
- 附件：小图片、PDF/Office、小表格可解析；大文件给中文限制提示。
- 办公工具箱：总结文档、分析表格、做 PPT、写邮件、处理文件、编码入口可选择并自动回普通模式。
- Skills/Plugins/Agents：打包后办公 skills、RTK、claude-mem、CodeGraph、默认 agents 可见。
- Computer Use：Windows 基础检查可用；macOS 权限缺失时显示可恢复引导。
- 支付/订阅：已激活用户 entitlement 正常刷新；额度耗尽和订阅过期为中文友好提示。

## 默认取舍

- 不引入新的服务端会话存储；第一轮优先用现有 `workDir/projectPath/messageCount/modifiedAt`。
- 快捷键 V1 不做用户自定义，只覆盖高频固定操作。
- 时间统计 V1 显示最后更新时间、消息数和运行中耗时；累计工作时长后续再做。
- 每个阶段完成后可单独发布，不等待 P0-P5 全部完成。
