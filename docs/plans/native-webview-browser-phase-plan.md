# 原生 WebView 浏览器 Phase Plan

## 总览

建议拆成 6 个 P：P0-P5。P0-P1 是技术闸门，P2-P5 才是产品体验打磨。

如果 P1 发现 Tauri child WebView 在 Windows 或 macOS 上无法稳定嵌入右侧工作台，就停止正式浏览器入口，只保留外部打开，不继续堆半成品。

## P0：方案确认与技术闸门

目标：

- 明确不再用 iframe 做正式浏览器。
- 明确浏览器是右侧工作台能力，不进入聊天上下文。
- 确认 Tauri 当前版本具备 child WebView API。
- 落地需求文档和阶段计划。

验收：

- 需求文档写清楚用户目标、非目标、安全边界。
- Phase Plan 写清楚每个阶段的通过条件。
- 本地确认 Tauri API 存在：`Window::add_child`、`Webview::navigate`、`Webview::set_bounds`。
- 明确 child WebView 依赖 Tauri `unstable` feature，发布前必须单独过 smoke。

## P1：原生 WebView 最小 Spike

目标：

- 在右侧工作台中创建一个原生 child WebView。
- 能打开固定 URL，例如 `https://www.baidu.com/`。
- 能在工作台关闭时隐藏或销毁。
- 能在工作台尺寸变化时同步位置和大小。

实现范围：

- 新增 Tauri browser state，按 `sessionId` 管理 WebView。
- 新增最小命令：`browser_create`、`browser_set_bounds`、`browser_hide`、`browser_close`。
- 前端只做内部调试入口或 feature flag，不作为正式用户入口。
- 先通过独立 target 目录执行 `cargo check`，避免运行中的 sidecar 锁住默认 target。

验收：

- Windows dev 环境创建成功。
- 工作台收起后不残留网页覆盖层。
- 拖拽工作台宽度后页面边界跟随。
- 窗口缩放后页面不丢失、不盖住聊天输入框。

## P2：地址栏、导航和外部打开

目标：

- 做成用户能理解的基础浏览器。

实现范围：

- 地址栏：URL、裸域名、搜索词归一化。
- 后退、前进、刷新、停止加载。
- loading 状态。
- 复制当前链接。
- 外部浏览器打开。
- 页面标题同步。

验收：

- 输入 `baidu.com` 能打开百度。
- 输入中文搜索词能搜索。
- 后退、前进、刷新能正常工作。
- 外部打开能打开当前 URL。

## P3：链接、新窗口、下载和错误处理

目标：

- 解决用户真正用网页时会遇到的边界。

实现范围：

- 普通链接跳转优先内置完成；复杂站点如果平台 WebView 表现不稳定，必须提供外部打开兜底。
- `target=_blank` 新窗口处理：默认提示外部打开，避免在主窗口里制造不可控子窗口。
- 下载事件处理：提示用户用外部浏览器下载。
- 特殊协议处理：外部打开或提示不支持。
- 加载失败中文错误页。

验收：

- 百度搜索结果可点击跳转。
- GitHub、网盘、登录页如果无法稳定内置跳转，必须显示中文提示并保留外部打开。
- 下载链接不静默失败。
- 失败时用户知道下一步怎么做。

## P4：布局联动与主题打磨

目标：

- 让浏览器像工作台的一等公民，而不是浮在页面上的异物。

实现范围：

- 工作台展开、收起、拖拽、窗口缩放的边界同步。
- 右侧工作台最小宽度和主面板最小宽度联动。
- 亮色、暗色、多主题下工具栏对比度正确。
- 小窗口下按钮不消失，URL 输入框可用。
- 切换到审查、文件、活动时浏览器隐藏。

验收：

- 1366x768、1280x720、小窗口都可操作。
- WebView 不遮挡输入框、顶部菜单、右侧按钮。
- 主题切换后工具栏仍清晰。

## P5：跨平台 Smoke 与发布闸门

目标：

- 达到内测可发布标准。

测试场景：

- Windows：百度、官网、普通链接跳转、外部打开兜底、下载链接提示。
- macOS：百度、官网、普通链接跳转、外部打开兜底、下载链接提示。
- GitHub、网盘、登录页作为增强 smoke；失败不允许静默，必须走外部打开兜底。
- 工作台拖拽和窗口缩放。
- 关闭工作台、切换会话、重启应用。
- 外部打开兜底。

发布闸门：

- P1-P4 验收全部通过。
- Windows/mac 至少各跑一轮 smoke。
- 失败时不会影响审查、文件、活动三个稳定视图。

手工 smoke 清单：

1. 打开任意会话，展开右侧工作台，切换到“浏览器”，默认应加载百度。
2. 在地址栏输入 `gugu.guxingyao.com` 或普通网址并回车，应自动补全协议并跳转；复杂站点失败时应提示外部打开。
3. 在地址栏输入中文搜索词，应跳转到搜索结果页。
4. 点击百度或官网页面里的普通链接，页面应在工作台内正常跳转，地址栏同步更新。
5. 点击会打开新窗口的链接时，不应静默失败；应显示中文提示，并可用“外部打开”继续。
6. 点击下载链接时，不应在内置浏览器里静默下载；应提示用外部浏览器下载。
7. 拖拽右侧工作台宽度、缩放窗口、切换亮色/暗色/多主题，页面区域应跟随边界，工具栏仍可见。
8. 切换到“审查 / 文件 / 活动”时，浏览器 WebView 必须隐藏，不遮挡其它视图。
9. 收起右侧工作台、切换会话、重启应用后，不应残留 WebView 覆盖层。
10. Windows 和 macOS 各跑一轮；macOS 重点看 WKWebView 登录页、外部打开、工作台收起后的隐藏行为。

自动化覆盖：

- `WorkbenchPanel.test.tsx` 覆盖浏览器入口、地址栏导航、恢复已有页面、长时间加载提示和工作台宽度联动。
- `desktop` 全量 Vitest 覆盖工作台、侧栏、输入框、设置页等桌面回归。
- `desktop` TypeScript no-emit 和 `desktop/src-tauri` cargo check 覆盖前后端类型与 Tauri 命令编译。

当前限制：

- jsdom 单测无法证明真实 WebView 的网页登录、下载、弹窗、复杂站点和平台差异。
- Tauri child WebView 仍依赖 `unstable` feature；发布前必须保留 P5 手工 smoke 作为闸门。

## 预估

- 可用 MVP：3-4 天。
- 做到比较稳：5-7 天。
- 做到接近 Codex 那种顺滑程度：1-2 周。
