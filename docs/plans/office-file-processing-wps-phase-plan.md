# Office 文件处理与 WPS 集成 Phase Plan

状态：Draft  
日期：2026-06-25

## Summary

建议拆成 7 个 P：P0-P6。第一轮目标不是“控制 WPS”，而是先把高频办公文件处理做稳。

核心顺序：

1. 先定义文件处理规范和测试样本。
2. 先做 xlsx/csv，因为用户需求最明确、可验证性最高。
3. 再接入前端运行链路和可见进度。
4. 再扩展 docx/pptx。
5. 最后做 WPS/Office 打开与发布验收。

## P0：需求固化与样本集

预计：0.5-1 天

目标：

- 固化 Office 文件处理需求和边界。
- 准备可重复测试的样本文件。
- 明确每类文件的 smoke case。

任务：

- 完成 `office-file-processing-wps-requirements.md`。
- 新增测试样本清单：
  - xlsx：单价、数量、金额。
  - xlsx：缺少目标列，需要新增列。
  - csv：去重、排序、筛选。
  - docx：简单替换、生成文档。
  - pptx：根据大纲生成、文本替换。
- 明确“不覆盖原文件”的默认策略。
- 明确失败文案模板。

验收：

- 需求文档和 Phase Plan 已 review。
- 每个样本都有输入、用户指令、期望输出。
- V1 不依赖用户安装 Python、qmd、sh。

## P1：表格本地处理 MVP

预计：2-3 天

目标：

- 支持 xlsx/csv 的本地 deterministic 处理。
- 先覆盖最典型的“金额 = 单价 * 数量”。

任务：

- 建立 Office 文件处理入口。
- 支持读取 xlsx 工作簿和工作表。
- 支持识别首行表头。
- 支持根据列名定位字段。
- 支持新增或更新目标列。
- 支持数值计算和基础类型转换。
- 支持保存为新文件。
- 支持 CSV 同类处理。

默认规则：

- 原文件不修改。
- 输出文件放在原目录。
- 文件名追加 `_gugu` 和时间戳。
- 默认写入数值，不写公式。

验收：

- 用户输入“计算金额这一列，金额=单价*数量”后生成新 xlsx。
- 新文件金额列正确。
- 原文件未修改。
- 缺少“单价”或“数量”时给出中文提示。
- 文件被占用时给出中文提示。

## P2：运行链路与前端反馈

预计：1-2 天

目标：

- 让用户能看见 Office 文件处理的过程和结果。
- 避免长时间“思考中”但不知道发生了什么。

任务：

- 在任务活动面板展示阶段：
  - 正在读取文件。
  - 正在识别表头。
  - 正在计算。
  - 正在写入新文件。
  - 已生成文件。
- 生成结果文件卡片。
- 增加“打开文件”和“在文件夹中显示”操作。
- 失败时展示“原因 / 影响 / 下一步”。
- 将 Office 文件编辑任务从普通附件解析中区分出来。

验收：

- 用户能看到处理进度。
- 成功后能直接打开结果文件。
- 失败时不是裸 Error。
- 不再把这类任务错误地交给纯模型总结。

## P3：表格能力扩展

预计：2-3 天

目标：

- 覆盖更多小白用户常见表格需求。

任务：

- 支持筛选。
- 支持排序。
- 支持去重。
- 支持拆表。
- 支持合并表。
- 支持按条件新增列。
- 支持基础统计。
- 支持多工作表选择。
- 样式、列宽、筛选器尽量保留，无法保留时明确提示。

验收：

- 常见 Excel/CSV 文件能完成基础清洗。
- 复杂格式不会导致原文件损坏。
- 无法处理时能给出可理解的限制说明。

## P4：Word / PPT 基础文件处理

预计：3-4 天

目标：

- 把“生成文档”和“生成 PPT”从纯文本输出推进到真实文件输出。

任务：

- docx：
  - 从 Markdown/TXT 生成 docx。
  - 简单文字替换。
  - 提取标题和正文。
- pptx：
  - 根据大纲生成基础 PPT。
  - 替换文本。
  - 从 PPT 导出大纲。
- 输出新文件。
- 结果展示文件卡片。

验收：

- “总结成 Word”能生成 docx。
- “做成 PPT 大纲/基础 PPT”能生成 pptx。
- 不覆盖原文件。
- 复杂模板和高级美化明确标记为后续能力。

## P5：WPS / Office 打开与预览

预计：1-2 天

目标：

- 让处理结果更容易被用户检查。

任务：

- 处理完成后一键打开文件。
- 默认走系统打开方式。
- 如果可检测到 WPS/Office，可作为增强提示。
- 打不开时提供“在文件夹中显示”。
- 文件被占用时给友好提示。

验收：

- Windows 上能用默认应用打开 xlsx/docx/pptx。
- macOS 上能用默认应用打开文件。
- 未安装 WPS 不影响文件处理。
- 已安装 WPS 时用户可以自然检查结果。

## P6：打包、发布与回归固化

预计：1-2 天

目标：

- 确保 Office 文件处理能力进入正式打包流程。

任务：

- 确认依赖进入桌面包。
- 确认 Windows/macOS 都可运行。
- 更新打包规范：
  - Office 文件处理不依赖用户安装 Python、qmd、sh。
  - 需要打进 skills。
  - 需要 smoke xlsx/docx/pptx。
- 增加发布前 checklist：
  - 新装。
  - 覆盖安装。
  - 热更新。
  - xlsx 金额计算。
  - docx 生成。
  - pptx 生成。
  - 打开结果文件。

验收：

- 打包后普通小白用户可直接处理基础 Office 文件。
- 没有宿主命令缺失提示。
- 发布 smoke 通过。

## 后续 P7+：深度应用适配器

这不是 V1 范围，但需要提前留好方向。

目标：

- 让 Gugu 能更好地操作 WPS、腾讯会议、浏览器等应用。

可能任务：

- 应用适配器注册表。
- 腾讯会议：预约会议、加入会议、复制会议信息。
- WPS：打开指定文件、另存为、导出 PDF。
- 浏览器：更稳定地识别页面和输入框。
- 每个应用单独权限和风险提示。

原则：

- 能文件级处理的，不走 UI 自动化。
- 必须 UI 自动化的，才走 Computer Use / 应用适配器。
- 高风险操作必须确认。

## 测试计划

### 单元测试

- 路径解析。
- 输出文件命名。
- 表头识别。
- 数字转换。
- 公式/数值写入。
- 缺列错误。
- 不覆盖原文件。

### 集成测试

- xlsx 金额计算。
- csv 去重排序。
- docx 生成。
- pptx 生成。
- 文件被占用。
- 文件不存在。

### UI 测试

- 进度阶段展示。
- 成功文件卡片。
- 打开文件按钮。
- 在文件夹中显示按钮。
- 失败中文提示。

### 发布 Smoke

- Windows 新装。
- Windows 覆盖安装。
- Windows 热更新。
- macOS 新装。
- macOS 权限和默认打开。
- skills/office 能力打包。

## 风险与应对

### 复杂格式保真

风险：

- Excel 样式、透视表、图表、宏可能无法完整保留。

应对：

- V1 明确只承诺基础数据处理。
- 输出新文件。
- 提示“复杂格式可能无法完全保留”。

### 文件锁定

风险：

- 用户正在用 WPS/Excel 打开文件，导致写入失败。

应对：

- 写入新文件。
- 如果仍失败，提示关闭占用文件后重试。

### 大文件性能

风险：

- 大 xlsx 处理慢或内存高。

应对：

- 显示进度。
- 设置大小限制。
- 超限时建议拆分或后续走专业模式。

### 模型误判

风险：

- Agent 把“处理 Excel”误当成普通问答或附件总结。

应对：

- Context Router 增加文件编辑意图。
- Office toolbox 明确路由。
- 对“生成/修改/填入/新增/替换/保存”等动词提高优先级。

## Handoff Notes

- `office-suite`、`excel-master`、`spreadsheet-master`、`word-master`、`ppt-master`、`local-office-files` 应继续作为 prompt 和 routing 层，不要承担二进制文件编辑主逻辑。
- deterministic 文件处理应该是本地 app-managed 能力。
- 默认生成新文件，不覆盖原文件。
- WPS 集成先做“打开结果”，不要一开始做 UI 操控。
- Computer Use / 应用适配器用于 V3，不要和 V1 文件处理混在一起。
