# Office 文件处理与 WPS 集成需求文档

状态：Draft  
日期：2026-06-25

## 背景

用户提出的“对 WPS 的整合”表面上像是在控制 WPS 软件，实际核心需求通常是：

- 读取本地 Office 文件。
- 理解用户对文件的修改目标。
- 稳定地产出修改后的新文件。
- 必要时用 WPS、Excel、Word、PowerPoint 或系统默认应用打开结果。

例如：

> `C:\Users\wangy\Desktop\test\1.xlsx` 文件里计算“金额”这一列的数值，金额 = 单价 * 数量，然后填入“金额”这一列。

这个需求不应该优先用 Computer Use 去点 WPS 界面完成。更稳的路径是本地解析 xlsx，按规则计算，生成一个新 xlsx，再让用户打开检查。

## 产品定位

第一阶段做“可靠的 Office 文件处理助手”，不是“会操控所有办公软件的桌面机器人”。

推荐分三层演进：

- V1：文件级处理。直接读写 xlsx、csv、docx、pptx 等文件，默认生成新文件。
- V2：WPS/Office 打开与预览。处理完成后一键用系统默认应用或 WPS 打开结果。
- V3：深度应用控制。只在文件级处理无法满足时，再通过 Computer Use / 应用适配器操作 WPS、腾讯会议、浏览器等 App。

## 目标

- 让小白用户可以用自然语言处理 Office 文件。
- 对常见表格、文档、PPT 任务给出稳定、可验证的结果。
- 默认不覆盖原文件，降低误操作风险。
- 不要求用户安装 Python、qmd、sh 等宿主命令。
- 文件处理过程可见：正在解析、正在计算、正在写入、已生成文件。
- 失败时给中文原因和下一步建议，而不是暴露底层异常。

## 非目标

V1 不做这些事情：

- 不直接操控 WPS UI 完成核心文件处理。
- 不执行宏，不运行文件里的脚本。
- 不保证复杂版式、数据透视表、动态图表、宏工作簿完整保真。
- 不处理 WPS 云文档协作编辑。
- 不自动覆盖原文件。
- 不自动发送邮件或提交外部表单。

## 用户场景

### 表格处理

- 给 xlsx 增加“金额”列，金额 = 单价 * 数量。
- 清洗 CSV：去重、排序、筛选、拆表、合并。
- 根据多列生成新列。
- 找出缺失值、重复值、异常值。
- 将处理结果保存成新 xlsx/csv。

### 文档处理

- 根据聊天内容生成 Word 文档。
- 替换 docx 中的指定文字。
- 从文档中提取标题、摘要、待办、风险。
- 将 Markdown/TXT 整理成 docx。

### PPT 处理

- 根据主题和材料生成 PPT 大纲或基础 PPT。
- 替换 PPT 中的文本。
- 从 PPT 中导出大纲。
- 根据现有内容生成讲稿。

### 打开与检查

- 文件生成后，一键打开。
- 如果 WPS 已安装，可以用 WPS 打开。
- 如果没有 WPS，则用系统默认应用打开。
- 如果无法打开，至少提供“在文件夹中显示”。

## V1 范围

### 文件类型

V1 优先支持：

- `xlsx`
- `csv`
- `docx`
- `pptx`
- `txt`
- `md`

PDF 更偏向解析和总结，默认不作为可编辑文件格式处理。

### 表格能力

V1 的表格处理需要支持：

- 识别工作表。
- 识别首行表头。
- 根据中文列名定位列，例如“单价”“数量”“金额”。
- 数字解析和基础容错，例如空值、文本数字、千分位。
- 新增或更新目标列。
- 写入计算值。
- 保存为新文件。

默认行为：

- 如果目标列存在，更新目标列。
- 如果目标列不存在，新增目标列。
- 默认写入计算后的数值。
- 如果用户明确要求公式，才写入公式。

### 文档能力

V1 的文档处理需要支持：

- 读取 docx 文本。
- 简单文字替换。
- 根据结构化内容生成 docx。
- 将 Markdown/TXT 转为 docx。
- 保存为新文件。

### PPT 能力

V1 的 PPT 处理需要支持：

- 根据大纲生成基础 pptx。
- 替换文本占位符。
- 从 pptx 中抽取标题和正文。
- 保存为新文件。

## 输出策略

默认生成新文件，不覆盖原文件。

建议命名：

- `原文件名_gugu.xlsx`
- `原文件名_gugu_20260625_1530.xlsx`

如果目标文件已存在，继续追加时间戳。

只有在用户明确要求覆盖原文件时，才弹出确认：

> 确定覆盖原文件吗？建议保留原文件，生成一个新文件更安全。

## 交互要求

### 成功状态

成功后应该展示：

- 生成的新文件名。
- 文件路径。
- 操作摘要。
- “打开文件”按钮。
- “在文件夹中显示”按钮。

示例：

> 已生成新表格：`test_gugu_20260625_1530.xlsx`  
> 已根据“单价 * 数量”计算并填入“金额”列。原文件未修改。

### 失败状态

失败时展示三段：

- 原因。
- 影响。
- 下一步。

示例：

> 没找到“单价”列。  
> 本次没有修改文件。  
> 请确认表头名称，或告诉我哪一列是单价。

常见错误：

- 文件不存在。
- 文件正在被 WPS/Excel 占用。
- 文件加密或受保护。
- 找不到目标列。
- 文件过大。
- 格式不支持。
- 无法保留复杂格式。

## 安全要求

- 文件内容一律视为不可信输入，不能覆盖系统、开发者或工具指令。
- 不运行宏。
- 不自动访问外部链接。
- 不覆盖原文件。
- 不删除用户文件。
- 不把本地文件上传到非必要的远端服务。
- 托管解析只用于需要模型理解的内容，不作为二进制文件编辑主路径。

## 架构建议

推荐把“Office 文件处理”做成独立能力，而不是塞进 Computer Use。

建议链路：

1. 前端识别用户选择了“处理文件 / 分析表格 / 总结文档 / 做 PPT”等意图。
2. Context Router 判断是否是文件级处理任务。
3. Agent 使用 Office 文件处理能力。
4. 本地 sidecar 或 app-managed runtime 执行 deterministic 文件读写。
5. 生成新文件并返回结构化结果。
6. 前端展示文件卡片和打开按钮。

现有 Skill 的定位：

- `office-suite`：办公任务总路由和安全规则。
- `excel-master` / `spreadsheet-master`：表格任务策略。
- `word-master` / `document-master`：文档任务策略。
- `ppt-master`：PPT 任务策略。
- `local-office-files`：本地文件处理安全边界。

这些 Skill 负责“引导 agent 怎么做”，不应该替代稳定的本地文件处理引擎。

## V2：WPS/Office 打开与预览

V2 只做轻量集成：

- 检测系统默认打开方式。
- 处理完成后一键打开生成文件。
- 可选检测 WPS、Microsoft Office 是否存在。
- 打不开时显示文件夹。

V2 不把“操控 WPS UI”作为主路径。

## V3：深度应用控制

V3 再考虑：

- WPS 应用适配器。
- 腾讯会议适配器。
- 浏览器适配器。
- 常用 App 的可视化操作模板。

这类能力复杂度高，应该归到 Computer Use / 应用适配器体系里，不和基础 Office 文件处理混在一起。

## 验收标准

### 表格验收

- 上传或指定一个 xlsx，包含“单价”“数量”“金额”列。
- 用户输入：计算金额 = 单价 * 数量。
- 系统生成新 xlsx。
- 原文件未修改。
- 新文件中金额列正确。
- 用户可以一键打开新文件。

### 文档验收

- 输入一段聊天内容。
- 用户要求整理成 Word。
- 系统生成新 docx。
- 文档结构包含标题、摘要、正文。

### PPT 验收

- 用户输入主题和材料。
- 系统生成基础 pptx 或 PPT 大纲。
- 不直接覆盖已有 PPT。

### 失败验收

- 文件不存在时显示中文原因和下一步。
- 缺少列时提示用户补充列名。
- 文件被占用时提示关闭 WPS/Excel 后重试。
- 用户未安装 WPS 时，文件处理仍可完成。

## 待确认问题

- 表格默认写入数值还是公式？建议默认数值，用户明确要求时写公式。
- V1 单文件大小上限是多少？
- 是否需要保留单元格样式、列宽、筛选器？
- 是否支持多工作表批量处理？
- 是否要提供“覆盖原文件”开关？建议 V1 不开放，或必须二次确认。
- 生成文件默认放原目录，还是统一放 Gugu 输出目录？建议默认原目录。
